== De onde veio a orientação a objeto? ==

1950 - Linguagem de baixo nível (assembly)
Dificuldade: A complexidade e a dificuldade de leitura e manutenção do código escrito em linguagem de máquina.

1955 - Linguagem linear (utiliza "goto()" para forçar o compilador a ir para outras linhas)
Dificuldade: O "código espaguete" gerado pelo uso excessivo de "goto", tornando o fluxo do programa confuso e difícil de depurar.

1960 - Linguagem estruturada (ALGOL e C) (mudança de linha automática pelo compilador)
Dificuldade: A dificuldade de reutilização de código e a complexidade de gerenciar projetos de software cada vez maiores.

1965 - Linguagem modular (módulos e pacotes isolados)
Dificuldade: A necessidade de modelar sistemas complexos de forma mais próxima ao mundo real, agrupando dados e comportamentos relacionados.

1970 - Linguagem orientada a objetos (módulos e pacotes isolados se comunicam entre si)
Paradigma da programação mais utilizado hoje em dia por suas vantagens e características.

Em suma, todo avanço tecnológico veio por conta de alguma necessidade ou desconforto relacionado à situação
naquele momento histórico em questão, como a crise do software de 1960.


== Para que estudar OO e vantagens de uso ==

Imagine um algorítmo orientado a objeto como um carro: um carro
é composto por diversos objetos diferentes, cada objeto é responsável pelo funcionamento
de uma parte do todo, e grande parte dos objetos comunicam-se entre si.


== As 6 grandes vantagens/características de OO ==

Mnemônico: "COMERNada" ajuda a lembrar.

1. Confiável: Isolamento entre as parte gera algo mais seguro. Ao alterar uma das partes, nenhuma outra é afetada.
Exemplo com carro: Ao trocar um pneu de um carro, não há a necessidade de alterar nenhuma outra parte do veículo.

2. Oportuno: Ao dividir tudo em partes, cada uma delas pode ser desenvolvida em pararelo.
Exemplo com carro: Durante a fabricação das partes de um veículo, cada parte é feita separadamente e, geralmente, simultaneamente, 

3. Manutenível: Atualizar é mais fácil. Uma pequena alteração vai beneficiar todas as partes relacionadas.
Exemplo com carro: Ao trocar o motor para um motor melhor, o carro inteiro é beneficiado com mais velocidade.

4. Extensível: Um sistema não deve ser estático. Tudo deve mudar e crescer para permanecer útil.
Exemplo com carro: Instalar uma carretinha ao carro para carregar mais carga.

5. Reutilizável: Objetos que foram criados para um sistema podem ser aproveitados em outros sistemas.
Exemplo com carro: O motor de um Gol é o mesmo motor de um Fox, pois são da mesma marca.

6. Natural: Mais fácil de entender. Maior atenção às funcionalidades do que aos detalhes da implementação.
Exemplo com carro: Para andar de carro o motorista não precisa saber como funciona a parte elétrica ou o funcionamento do motor.

Importante: Todas essas características só são possíveis se o objeto em questão seguir o padrão e planejamento do projeto.

== O que é classe e objeto? ==

Classe: Formato/padrão a ser seguido sempre que eu precisar fazer objetos do mesmo tipo ou que tenha as mesmas características/comportamentos.

Objeto: Um objeto é uma coisa material ou abstrata feita a partir de uma classe e pode ser descrita por meio de seus atributos,
metodos e estado atual.

Exemplo didático: Biscoitos (objeto) de mesmo formato são assim por conta de uma forma (classe).

     Diagrama UML (United Modeling Language)
        ------------------------------
        |         NomeClasse         |
        ------------------------------
        |  Características da classe | <- Atributos
        ------------------------------
        |    Coisas que pode fazer   | <- Métodos
        ------------------------------

                   Exemplo:
        ------------------------------
        |      BiscoitoCoracao       |
        ------------------------------
        |  + tamanho                 |
        |  + massa                   |
        |  + peso                    |
        |  + cobertura               |
        |  + cozido                  |
        |  + temperatura             | 
        ------------------------------
        |  + cozinhar()              | 
        |  + congelar()              |
        |  + cobrir()                |
        |  + confeitar()             |
        |  + podeComer()             |
        |  + comer()                 | 
        ------------------------------

A principal diferença de um objeto e uma struct em C, por exemplo, é que a struct só recebe dados, enquanto um objeto,
além de poder receber dados, também executa ações através de métodos.


== Instância ==

Momento em que um objeto é gerado por uma classem, ou seja, um objeto é uma instância de uma classe.

Exemplo didático: Momento em que a forma (classe) é pressionada em uma massa de biscoito, resultando em uma massa com formato de biscoito (objeto).


== Estado de um objeto ==

Vamos pegar novamente um biscoito por exemplo que tenha os seguinte atributos:

tamanho = 8.2cm
massa = baunilha
peso = 54.3g
cobertura = pistache
cozido = True
temperatura = 55ºC

Os valores dos atributos de OBJETOS são os ESTADOS.

  Tonalidade: Sol maior, 
  Estilo: Erudito
